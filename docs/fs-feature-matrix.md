# 自前実装の FS の対応機能と、上流への追従

XFS・Btrfs・F2FS (と NTFS) は自前の読み取り・書き込み実装で、ext4・FAT・exFAT・squashfs・erofs・isofs・UDF はカーネルのコードを流用している。流用側はカーネルの更新に合わせて移植し直す。**自前側は、新しい機能が mkfs の既定になるたびに、対応するかどうかを決める必要がある**。それを見落とさないための仕組みがこの文書。

## 方針

| | 方針 |
|---|---|
| 読み取り | 最新の mkfs の既定で作ったイメージは読めることを目標にする。読めない機能は、マウントを拒否して理由を返す (黙って間違った内容を見せない) |
| 書き込み | 許可リスト方式。リストに無い機能が 1 つでもあれば読み取り専用に落ちる。新しい機能は、検証 (カーネルの fsck・実機・クラッシュ試験) が済んでから許可リストに足す |
| 知らないフラグ | 必ず拒否 (読み取りも)。読み取りに影響しないと分かっているもの (Btrfs の compat_ro など) だけ許可 |

## 対応表 (`tools/fs_feature_matrix.json`)

機能フラグごとに状態を持つ。`rw` = 読み書きできる、`ro` = マウントできるが書き込みは拒否、`refused` = マウント自体を拒否。表の根拠は、各 FS の docs (`xfs-write.md`、`btrfs-port.md` / `btrfs-write.md`、`f2fs-write.md`) とコード (`core/compat/src/{xfs,btrfs,f2fs}_volume.cpp`)。**対応範囲を変えたら、この表も同じ変更で直す**。

## 検査 (`tools/check_mkfs_defaults.py`、`.github/workflows/mkfs-defaults.yml`)

最新の mkfs の既定で小さなイメージ (一時ディレクトリの疎ファイル、root 不要) を作り、スーパーブロックのフラグを読んで、表と突き合わせる。

| 結果 | 意味 | 終了コード |
|---|---|---|
| OK | 既定のフラグがすべて表にあり、すべて `rw` | 0 |
| GAP (既知の穴) | 表にはあるが、`ro` / `refused` の機能が既定で立っている。そのイメージはアプリで読み取り専用になる / 開けない | 0 (`--strict` で 2) |
| NEW | 表に無いフラグが既定で立っている。**対応方針を決めて、表と docs を直す** | 1 |

CI は ubuntu-latest (安定版・古め) と Arch Linux のコンテナ (ローリング・最新に近い) の 2 つで動かす。実行は、手動 (`workflow_dispatch`)、`usbmem-mkfs-defaults` ブランチへの push、週 1 回の `schedule`。GitHub の仕様で、`schedule` はリポジトリの既定ブランチにファイルがあるときだけ動く。既定ブランチに置けない間は、手動か push で動かす。

## 2026-11-14 時点の結果 (手元: mkfs.xfs 7.2.0、btrfs-progs 7.1、f2fs-tools 1.16.0)

- **XFS: GAP**。既定で `rmapbt` (ro_compat) と `parent_pointer` (incompat) が立つ。どちらも読み取りは可、書き込みは拒否。実機・CI のテスト用イメージは `-m rmapbt=0 -n parent=0` で作っている。**最新の mkfs.xfs で作った XFS は、今のところアプリで読み取り専用になる**。書き込み対応の候補: rmapbt の更新、parent pointer の更新 (どちらも新規作成・削除でメタデータの更新が増える)。
- Btrfs: OK (block_group_tree を含め、既定のフラグはすべて読み書き可)。
- F2FS: OK (1.16.0 の既定は機能なし)。

## 新しい機能が見つかったときの手順

1. `check_mkfs_defaults.py` が NEW を報告する (CI が失敗する)。
2. その機能の意味を調べる (上流のカーネル・mkfs のドキュメント)。読み取りに影響するか、書き込みだけか。
3. 読み取りに影響する → リーダーを対応させ、`ro` か `rw` にする。しない → マウントを拒否 (`refused`) にしておく。
4. 書き込みを許可するなら、カーネルの fsck・クラッシュ試験・実機で確かめてから `rw` にする。
5. 表・docs・コードの許可リストを、同じ変更で直す。
