# プライバシーと権限 — INTERNET 権限の使い方・保存するもの・Google Play の申告の下書き

状態 (2026-11-24): 草稿。**事実の節 (1〜4 章) はコード (`AndroidManifest.xml`、`smb/`、`KeystoreVault.kt`) を読んで確かめたもの**。5 章 (Play の申告) と 6 章 (プライバシーポリシーの雛形) は、公開準備 (docs/TODO.md の 10 番) で提出する文面の下書きで、提出前に最新の Play のポリシー・用語の定義と照らして確認する。公開版 (Apache-2.0。docs/editions.md) に含める。

要点:

- このアプリが**ネットワークへ出るのは SMB (ネットワーク共有) の機能だけ**で、**利用者が接続を作って「マウント」または「接続テスト」を押したときだけ**、利用者が入力したサーバーへ通信する。
- 開発者のサーバーへは何も送らない。解析 (アナリティクス)・広告・クラッシュ送信・自動更新の確認・テレメトリは**無い** (依存ライブラリにも無いことを 3 章で確かめた)。
- USB ストレージ・ディスクイメージ・暗号ボリュームの機能は、**通信しない**。ファイルの中身・パスワードは端末の外へ出ない。
- Google ドライブのバックアップ・端末間の移行には、**何も含めない** (保存した接続とパスワードも含めない)。

## 1. INTERNET 権限を使う機能は SMB だけ

| 項目 | 内容 |
|---|---|
| 権限 | `android.permission.INTERNET` (`AndroidManifest.xml`。インストール時に付く通常権限で、実行時の許可ダイアログは出ない) |
| 使う機能 | 「ネットワーク」タブの SMB (NAS・PC の共有フォルダー) の接続だけ。`smb/SmbRemoteFs.kt` (SMBJ) の TCP ソケット |
| 通信が始まる操作 | (1) 接続の編集画面の「接続テスト」、(2) 保存した接続の「マウント」。この 2 つだけ。アプリの起動・画面を開く・バックグラウンドでは通信しない |
| 通信しない操作 | USB の読み書き、イメージ・暗号ボリュームのマウント、ディスクツール、他のアプリから SAF 経由で USB を読む操作 (これらはソースに `java.net` の使用が無い。`tools/check_manifest_permissions.py` が、ネットワーク API を使うソースがあるのに権限が無い場合 / 権限があるのに根拠が無い場合に CI で失敗させる) |
| 切断・再接続 | マウントした共有が切れたら、自動で再接続しない (パスワードをメモリに残さないため)。利用者がもう一度「マウント」したときだけ通信する (docs/smb.md 5・12 章) |
| 常駐 | バックグラウンドのサービス・ワーカー・アラームで通信するものは無い。マウント中の接続は、アプリのプロセスが生きている間の TCP 接続 (キープアライブ) だけ |

## 2. 通信先

- **通信先は、利用者が接続の設定に入力したホスト名 (または IP アドレス) とポート (既定 445) だけ**。アプリに通信先のリスト・既定のサーバー・「おすすめ」は無い。
- 開発者のサーバー、解析・広告・クラッシュ送信のサービスへは**通信しない**。そのようなライブラリは依存に入っていない (依存は 3 章)。
- ネットワーク上の機器の探索 (mDNS / NetBIOS のブロードキャスト) もしない。ホスト名か IP を利用者が入力する (docs/smb.md 12 章)。
- 通信の暗号化は SMB のバージョンと設定による。SMB 3 の暗号化 (AES-128/256-GCM・CCM) と署名に対応し、接続の設定で「暗号化を必須にする」「署名を必須にする」を選べる (暗号化を必須にすると、暗号化できないサーバーには接続しない)。必須にしなければ、サーバーが求めない限り、SMB の中身は暗号化されない (署名で改ざんは検出する)。認証は NTLMv2 で、パスワードそのものはネットワークに流れない (ハッシュによる応答)。SMB 1 は実装しておらず、話せない。
- ネットワーク権限の周辺: `ACCESS_NETWORK_STATE` は使わない (ネットワークの状態を問い合わせない)。VPN・プロキシの設定は端末のものにそのまま従う (アプリで上書きしない)。

## 3. 保存するもの・保存場所・削除方法

### 3.1 SMB の接続の設定 (利用者が入力したもの)

| 内容 | 保存先 | 備考 |
|---|---|---|
| 接続名・ホスト名または IP・ポート・共有名・ドメイン (任意)・ユーザー名・SMB の最小バージョン・暗号化 / 署名を必須にするか、端末内の識別子 (ランダム。ホスト名などを含まない) | アプリ専用の `SharedPreferences` (`usbmem_smb`、JSON。`SmbStore`)。アプリ専用領域で、ほかのアプリは読めない。**平文** (パスワードを含まない) | 接続名・ホスト名・ユーザー名は、利用者が入力した文字列そのもの。端末の外へは送らない |
| パスワード | **既定では保存しない** (マウントのたびに入力)。メモリ上では、使ったあと配列をゼロで埋める。ログ・例外のメッセージには出さない | docs/smb.md 4 章 |
| パスワード (「パスワードをこの端末に保存する」を選んだときだけ) | `usbmem_vault` の `SharedPreferences` に、**Android Keystore の AES-256-GCM 鍵で暗号化した暗号文**だけ (`KeystoreVault.kt` の `PrefsVaultStore`)。鍵は Keystore の中にあって取り出せない。使うたびに生体認証または画面ロックを求める (`USE_BIOMETRIC`)。端末に画面ロックが無いなど、安全に保存できないときは、保存を選べない | 鍵の別名・保存の ID は `smb:<接続 id>` |
| マウント中の共有の記録 | メモリだけ (`SmbMounts`)。アプリのプロセスが終われば消える | |

### 3.2 USB・イメージ・暗号ボリュームの設定 (通信しない機能)

- マウントしたイメージの URI の記録・読み取り速度の調整値 (`usbmem_tuning`)・画面の設定 (`usbmem_settings`)・暗号ボリュームのパスワードを記憶したときの暗号文 (3.1 と同じ `usbmem_vault`)・ディスクツールの作業ファイル (`files/disktools` の復元の進行記録など)。すべてアプリ専用領域で、端末の外へ送らない。
- **USB メモリの中身・ディスクイメージの中身は、アプリが保存しない** (読み書きは利用者が選んだ対象に対してだけ)。ファイルを他のアプリへ見せるのは、利用者が使う SAF (ファイルアプリの「ドキュメント」の仕組み) 経由で、システムの権限のあるもの (`MANAGE_DOCUMENTS`) だけが呼べる。
- ログ (`logcat`) には、デバイス名・マウントの結果・エラーコードが出ることがある (端末内のログ。アプリは外へ送らない)。**パスワード・ユーザー名・ホスト名・共有のパスはログに出さない** (SMB のコードに `Log` の呼び出しは無く、例外のメッセージは固定の英文)。

### 3.3 バックアップ・端末間の移行

- `allowBackup="false"` に加えて、`dataExtractionRules` (Android 12 以降) と `fullBackupContent` (Android 11 以前) で、**全部のドメイン (`file` / `database` / `sharedpref` / `root` / `external`) を、クラウドバックアップにも端末間の移行にも含めない**と明示した (`res/xml/data_extraction_rules.xml`・`backup_rules.xml`)。
- つまり、保存した接続の設定 (ホスト名・ユーザー名) もパスワードの暗号文も、Google ドライブのバックアップや端末の引っ越しには入らない。新しい端末では、接続を作り直して、パスワードも入れ直す。Keystore の鍵はもともと端末の外へ出ない。

### 3.4 削除する方法

| 消したいもの | 方法 |
|---|---|
| ある接続の設定とパスワード | 「ネットワーク」タブで接続の「削除」。設定・保存したパスワードの暗号文・Keystore の鍵・マウントを消す (サーバーのファイルには何もしない)。試験 `SmbTest.passwordIsNotStoredByDefaultAndSavedOnlyEncrypted` で、削除後に残らないことを確認している |
| 保存したパスワードだけ | 接続の編集で「パスワードをこの端末に保存する」をオフにして保存するか、マウントの画面の「保存したパスワードを削除」 |
| 全部 | 端末の「設定 > アプリ > (このアプリ) > ストレージ > データを削除」、またはアンインストール (アプリ専用領域と Keystore の鍵が消える) |
| 開発者側のデータ | **無い** (開発者は何も受け取っていないので、削除の依頼を受ける対象もない) |

## 4. 権限の一覧と使う理由

`AndroidManifest.xml` が宣言するもの (これで全部。ストレージ・位置情報・連絡先・カメラ・マイクなどの権限は**要求しない**)。

| 権限・機能 | 種類 | 使う理由 |
|---|---|---|
| `android.permission.INTERNET` | 通常権限 (インストール時) | SMB (ネットワーク共有) への接続だけ (1 章) |
| `android.permission.USE_BIOMETRIC` | 通常権限 (インストール時) | 暗号ボリューム・SMB のパスワードを「記憶」するとき、Keystore の鍵を使うために生体認証 / 画面ロックを求める (`BiometricManager.canAuthenticate`・`BiometricPrompt`)。無いと「記憶する」の選択肢が出ない (docs/crypto-volumes.md) |
| `android.hardware.usb.host` (`uses-feature`、`required="false"`) | 機能の宣言 | USB メモリ・外付けディスクを直接読み書きする (USB Host)。対応していない端末でも、ディスクイメージを開く機能は使えるので、必須にしない |
| USB デバイスへのアクセス許可 (実行時) | システムの許可ダイアログ (`UsbManager.requestPermission`) | 接続した USB 機器ごとに、利用者が「許可」を選んだものだけにアクセスする。マニフェストの権限ではない |
| `<queries>` `org.usbmem.kfsd` | パッケージの可視性 (Android 11 以降) | 個人版の別 APK (kfsd のプラグイン) が入っているかを探す。公開版では該当のプラグインを配らない |
| ストレージ (`READ/WRITE_EXTERNAL_STORAGE`・`MANAGE_EXTERNAL_STORAGE`・メディア権限) | **要求しない** | ファイルは SAF (`ACTION_OPEN_DOCUMENT` など、利用者が選んだものだけ) 経由で扱う。全ファイルへのアクセスは不要 |
| `<provider>` `NtfsDocumentsProvider` (`MANAGE_DOCUMENTS` を要求) | コンポーネント | USB・SMB の中身を、システムのファイルアプリ (Documents UI) と、利用者が許可したアプリへ見せる。`MANAGE_DOCUMENTS` を持つのはシステムだけなので、他のアプリが直接は呼べない |
| `<service>` (kfsd・wimfuse、`exported="false"`) | コンポーネント (個人版のビルドだけ) | GPL 系の FS ドライバを別プロセスに分けて動かす。アプリの外へは公開しない |
| 通知・位置情報・Bluetooth・連絡先・カメラ・マイク・フォアグラウンドサービス・起動時の自動実行 | **要求しない** | 使わない |

## 5. Google Play のデータセーフティ (Data safety) の申告の下書き

(Play Console の入力項目の順。**提出時に、最新の定義と画面の文言を確認して直す**。)

### 5.1 データの収集と共有

| 質問 | 回答 | 根拠 |
|---|---|---|
| アプリは、ユーザーデータを収集または共有するか | **いいえ (収集なし・共有なし)** | 開発者のサーバー・第三者のサービス (解析・広告・クラッシュ送信) へ何も送らない (2 章)。ネットワークに出るのは、利用者が自分で入力したサーバー (自分の NAS・PC) への SMB だけで、利用者の操作でファイルを読み書きする通信 |
| 収集するデータの種類 | なし | |
| 共有するデータの種類 | なし | |

注意 (申告の根拠の説明):

- 利用者が自分で選んだ自分のサーバーへ、利用者の操作でファイルを送受信する通信は、開発者や第三者への「収集」「共有」ではないと考える (Play の定義で、「ユーザーが開始した転送」「ユーザーが選んだサービスへの転送」は共有から除かれる扱いがある)。**この解釈は、提出時に最新の Play の定義 (「収集」「共有」の項と、例外の項) で確認する**。迷う場合の代案は、「ファイルとドキュメント」を「収集 = はい、共有 = いいえ、目的 = アプリの機能、ユーザーが選んだ宛先への転送」と申告し、収集するのは利用者のサーバーへ送るデータで、開発者は受け取らないと説明欄に書く。
- アプリが端末内でだけ処理して、端末の外へ出さないものは、「収集」に当たらない (USB・イメージの中身、暗号ボリュームのパスワード)。

### 5.2 セキュリティの習慣

| 質問 | 回答 | 補足 |
|---|---|---|
| データは転送中に暗号化されるか | 「収集するデータが無いので該当なし」。聞かれた場合は、**「いいえ (一部のみ)」と正直に答える**: SMB 3 の暗号化は、接続の設定で「暗号化を必須にする」を選んだとき、またはサーバーが求めたときだけ。SMB 2.x や暗号化を必須にしない SMB 3 では、署名はあるが暗号化はない | 「暗号化を必須にする」を既定にするかは、判断が要る (既定にすると、暗号化に対応しない NAS には繋がらない)。docs/smb.md 12 章 |
| ユーザーがデータの削除をリクエストできるか | 「はい」: アプリ内で接続・保存したパスワードを削除でき (3.4 章)、アンインストール / データの削除で全部消える。開発者側にデータは無い | |
| Google Play ファミリーポリシーの対象か | 対象としない (子ども向けではない) | |
| 独立したセキュリティ審査 | 受けていない | |
| 緊急の更新・脆弱性への対応 | プライバシーポリシーの連絡先で受け付ける | |

### 5.3 その他の申告

- アプリの権限の宣言: 4 章の表のとおり (特別な権限・危険な権限なし)。`INTERNET` の使い道を聞かれたら、「ユーザーが追加した SMB サーバーへの接続のため」。
- 「広告 ID の使用」: いいえ。「アプリはロックダウン・テレメトリ・解析 SDK を含むか」: いいえ。
- ターゲット層: 一般の利用者 (ファイル管理)。
- データの暗号化に関する輸出管理 (アメリカの輸出規制の暗号の申告) は、別の手続き: 通信の暗号 (TLS ではなく SMB の署名・AES) と BouncyCastle (MIT) を同梱する。**提出前に、暗号の輸出区分の自己分類を確認する** (docs/TODO.md の公開準備 10 番に追記)。

## 6. プライバシーポリシーの雛形 (日本語)

---

**プライバシーポリシー — <アプリ名>**

制定日: <年 月 日>　最終更新: <年 月 日>

<アプリ名> (以下「本アプリ」) は、USB メモリ・外付けディスク・ディスクイメージ・ネットワーク共有 (SMB) のファイルを、Android 端末から読み書きするためのアプリです。本アプリの提供者 (以下「提供者」) は、利用者のプライバシーを尊重し、次のとおり情報を取り扱います。

**1. 提供者は、利用者の情報を収集しません**

本アプリは、利用者の個人情報・ファイルの中身・パスワード・端末の識別子・利用状況を、提供者のサーバーにも、第三者にも送信しません。解析ツール・広告・クラッシュレポートの送信機能は含みません。

**2. ネットワークへの通信**

本アプリがインターネットまたはネットワークへ通信するのは、利用者が「ネットワーク」の画面で SMB の接続を作成し、「接続テスト」または「マウント」を実行したときだけです。通信先は、利用者が入力したサーバー (ホスト名または IP アドレス、ポート) だけで、その通信では、利用者が操作したファイルの内容・ファイル名・認証情報 (ユーザー名と、NTLM による認証の応答) が、そのサーバーに送られます。通信の暗号化は、SMB の設定によります (接続の設定で暗号化を必須にできます)。サーバーの運営者による情報の取り扱いは、本ポリシーの対象外です。

USB メモリ・ディスクイメージ・暗号ボリュームの機能は、通信しません。

**3. 端末内に保存する情報**

本アプリは、次の情報を端末内のアプリ専用の領域に保存します。これらは提供者には送信されません。

- SMB の接続の設定 (接続名・ホスト名・ポート・共有名・ドメイン・ユーザー名・オプション)
- 利用者が「パスワードを保存する」を選んだ場合のパスワード。Android Keystore の鍵で暗号化して保存し、使うときに生体認証または画面ロックを求めます。選ばない場合、パスワードは保存しません。
- 暗号ボリュームのパスワードを「記憶」した場合の暗号化された情報 (同上)
- 画面の設定・転送速度の調整値などの設定

これらの情報は、Google ドライブのバックアップや端末間の移行の対象にしていません。

**4. 情報の削除**

本アプリの「ネットワーク」の画面で接続を削除すると、その接続の設定と保存したパスワードを消去します。端末の設定からアプリのデータを削除するか、アンインストールすると、本アプリが保存した情報はすべて消去されます。提供者は利用者の情報を保有していないため、提供者に削除を依頼する必要はありません。

**5. 権限**

本アプリは、ネットワークへの通信 (INTERNET: SMB のため)、生体認証の利用 (USE_BIOMETRIC: パスワードの保存のため)、USB 機器へのアクセス (利用者が許可した機器のみ) を使用します。ストレージ全体へのアクセスは要求せず、利用者が選んだファイルだけを扱います。

**6. 子どものプライバシー**

本アプリは、13 歳未満の子どもから情報を意図的に収集しません (そもそも、誰からも収集しません)。

**7. 変更**

本ポリシーを変更するときは、このページで告知します。

## 7. 検証・保守の手順

- **コードを変えたときの確認**: (1) 新しいネットワーク通信を足したら、この文書の 1・2 章と Play の申告を直す (`tools/check_manifest_permissions.py` は権限の漏れ・余りだけを見る)。(2) 新しく端末に保存するものを足したら、3 章を直し、バックアップから外れていることを確認する (`res/xml/*.xml` の規則は全ドメインを除外しているので、新しい保存先も自動で対象外)。(3) 依存ライブラリを足したら、通信・計測・広告の機能が無いことを確かめる (POM と jar の中の `java.net`・URL・analytics の有無)。
- **SMBJ の依存 (smbj・bcprov・slf4j-api・mbassador・asn-one) に、通信の機能 (解析・更新確認) が無いこと**: smbj は SMB のソケットだけ。slf4j-api はバインディングが無く何も出力しない。ほかは暗号・イベントバス・ASN.1 のライブラリ (docs/smb.md 7 章)。
- **残る確認 (未)**: 実機での、Google ドライブのバックアップからの除外の確認 (`adb shell bmgr` / `adb shell dumpsys backup` で、このアプリが対象にならないこと。手元の端末・AVD は使わない方針なので、公開前に別途)。
